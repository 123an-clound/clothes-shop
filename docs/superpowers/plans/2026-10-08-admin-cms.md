# Admin CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/admin` CMS: dashboard stats, products (variants matrix + multi-image upload), categories, orders (status/payment), Theme Builder with live preview, store/SEO/shipping/bank/policies settings — all applied to the live site without redeploy.

**Architecture:** Admin pages live outside the `(store)` group (no storefront chrome), gated three times: `proxy.ts` (`cs_is_admin` RPC), `requireAdmin()` in every page/action, and RLS/`security definer` checks in the DB. Multi-table writes go through atomic RPCs (`cs_admin_save_product`, existing `cs_admin_update_order`); single-table writes (categories, settings) use the session client under admin RLS. Images upload browser → Supabase Storage (`cs-products`, admin-only write policy, 5MB + mime limits enforced by the bucket) so files never pass through Server Action body limits. Every write calls `updateTag(CATALOG_TAG | SETTINGS_TAG)`.

**Tech Stack:** Next.js 16 Server Actions, Supabase (RPC, Storage), Zod 4 (strict write schemas, no `.catch`).

**Spec:** `docs/superpowers/specs/2026-10-07-clothes-shop-design.md` (§4 Admin, plan.md §4)

## Global Constraints
- Admin write schemas are strict (reject, never coerce). Read schemas keep `.catch` fallbacks.
- Bank picker uses BINs verified from `https://api.vietqr.io/v2/banks` (2026-10-08).
- Product slug auto-generated from name (Vietnamese diacritics stripped), editable, `^[a-z0-9]+(-[a-z0-9]+)*$`.
- Unique-violation errors mapped to Vietnamese messages (slug, SKU, size+color).
- `ponytail:` dashboard aggregates in one SQL function; fine for a small shop, add materialized stats if orders grow large.
